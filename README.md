## 先算清楚要多少机器

七日杀服务端吃多少内存，跟着三件事走：同时在线人数、地图规模（随机生成的大地图比 Navezgane 吃得多）、血月那一晚的僵尸量。官方脚本给出的门槛是 **4 GB 内存配 10 GB 磁盘**，想跑安稳一点给到 6 GB 和 20 GB。

| 同时在线 | 内存 | CPU | 上传带宽 | 说明 |
| --- | --- | --- | --- | --- |
| 2–4 人 | 4 GB | 2 核 | 10 Mbps | 最低可跑，血月前后容易吃紧 |
| 5–8 人 | 6–8 GB | 2–4 核 | 10–20 Mbps | 主流小圈子，6 GB 起步更从容 |
| 10–20 人 | 16 GB | 4 核 | 20 Mbps 以上 | 公开服起点，磁盘建议 NVMe |
| 30 人以上 | 32 GB | 8 核 | 20 Mbps 以上 | 需要固定公网 IP |

这里有两套常见的数字，容易看混。4 GB / 6 GB 是“服务端能不能起来、跑不跑得稳”的口径；8 GB 对应 10 人以下、16 GB 对应 20 到 30 人，是“稳定带人”的口径。两者不矛盾，差的是余量。你只打算三两个人周末玩，4 GB 完全够；准备开个长期档、朋友随进随出、地图又会越滚越大，直接上 6 GB 或 8 GB 省心。

带宽这栏比内存更容易被忽略。**上传 10 Mbps 是底线，10 人以上建议 20 Mbps**。很多家用宽带下载 500M、上传只有 30M，还是共享的，晚上一开就掉。租机器的时候看清“上传”那一栏，不是看“带宽 100M”这种笼统写法。

内存不够的症状很直白：服务器无预警退出，日志里搜得到 `OutOfMemoryException`。磁盘不够则是存档写入失败、地图加载卡住。

共享公网 IP 不等于不能开服，端口是按规则映射到你名下的，朋友连你的 IP 加端口就行。它的实际影响在于：给别人报地址的时候报的是“IP:端口”，端口变了地址就变；公开服挂出去、被扫端口的人盯上时，你能做的隔离比独立 IP 少一层。

下单前建议先问清三件事：控制台里能不能自己加 UDP 端口段、能不能拿到完整 root 或者面板里的文件管理权限（七日杀要改 serverconfig.xml 和往 Mods 目录丢东西）、以及面板的预装游戏列表里到底有没有 7 Days to Die。有就省事，没有也能自己用 SteamCMD 装，只是要确认机器允许访问 Steam。

## 装服务端：记住 AppID 294420

七日杀专用服务器的 Steam AppID 是 **294420**，装的时候匿名登录就够，不需要买过游戏的账号：


steamcmd +login anonymous +app_update 294420 validate +quit


Windows 手动流程大致是：建 `C:\steamcmd` 目录，下载 SteamCMD 压缩包解压进去，命令行 `cd C:\steamcmd` 后运行 `steamcmd`，等它自己更新完输入 `quit`。然后用记事本写一个 bat 文件，内容就是上面那行命令，双击执行，服务端会落到 `steamapps\common\7 Days To Die Dedicated Server` 下面。

Linux 上有现成的一键方案。有个开源项目把安装、自动更新和 systemd 服务管理打包好了，要求 Debian 12 以上，物理机、虚拟机、Proxmox 容器都行，需要 root 和能访问 Steam。它提供这几条命令：


7d2d_start     # 启动
7d2d_stop      # 停止
7d2d_restart   # 重启，重启前先自动更新
7d2d_status    # 看状态
7d2d_log       # systemd 日志，启动报错看这里
7d2d_serverlog # 游戏日志，玩家进出和事件看这里


默认服务端在 `/opt/7d2d-server/`，更新日志在 `/var/log/7d2d-update.log`，服务配置在 `/etc/systemd/system/7d2d.service`。它依赖 `curl`、`xmlstarlet`、`steamcmd`，脚本会自动装。

## Windows 还是 Linux

Windows 的优势是所见即所得：记事本改 serverconfig.xml，远程桌面进去看窗口，出问题直接看弹窗。代价是要系统许可证，同样配置的价格比 Linux 高，图形界面本身也占内存。

Linux 的好处有三条很实际：服务端不跑图形，资源全给游戏；systemd 托管后能做到无人值守，房主关电脑、断网都不影响存档；长期开机的稳定性更好，一台机器挂一年不重启是常见用法。代价是你得接受命令行。

判断规则简单：你熟哪个用哪个，短期玩几天用 Windows 省事，准备长期挂着就上 Linux。别照抄几年前教程里的 Windows Server 2012 R2，那个系统 2023 年 10 月就结束扩展支持了，现在再装是给自己找麻烦，起步用 2019 或 2022。

## 端口、协议，以及“服务器明明在线却连不上”

端口是七日杀开服最容易出错的地方，因为不同教程写的范围不一样。按最完整的配：**TCP 26900 单端口，加上 UDP 26900 到 26903 这一段**。


TCP 26900        → 服务器IP:26900
UDP 26900-26903  → 服务器IP:26900-26903


有教程只写 26900，也有写到 26902 的，漏掉的那几条 UDP 就是“服务器在列表里看得见，点进去一直转圈”的常见原因。如果你在配置里把 `SERVER_PORT` 改成别的，这一整套要跟着改。

协议这边要两个都开着。七日杀同时支持 LiteNetLib 和 SteamNetworking：前者是直连的主协议，走你转发的端口，延迟低；后者是回退通道，走 Steam 自己的网络，延迟略高但在 NAT 打洞失败时能救回来。对应配置项是 `DISABLED_NETWORK_PROTOCOLS`，**留空表示两个都启用**，官方推荐就是这个状态。有人为了“干净”把它填上，结果就是外面连不进来、局域网正常。

典型的失败症状：服务器出现在浏览器里，点击连接失败，报 **“Could not retrieve Server ID”**，而你自己在局域网里连得好好的。按这个顺序查：

1. 从外网机器验端口：`nmap -Pn -p 26900 你的公网IP`，TCP 通不通先确认。
2. 确认 `DISABLED_NETWORK_PROTOCOLS` 是空的。
3. 确认 `SERVER_REGION` 跟你服务器的实际位置一致（Europe、NorthAmericaEast 这些），填错会影响匹配。
4. Linux 服保持 `ALLOW_CROSSPLAY="false"`。
5. 重启服务端，改完配置必须重启才生效。

还有一个几乎没人写进教程的：**`GameName` 里不能有冒号**。带冒号的世界名会让 Windows 客户端直接连不上，Linux 和 Mac 客户端却正常，排查起来很费时间。

端口被占用是另一类问题。Windows 用 `netstat -ano | findstr 26900`，Linux 用 `ss -tulnp | grep 26900`，能看出谁占了。

没有公网 IP 的情况分两种：三个人以内，可以用异地组网工具把大家拉进同一个虚拟局域网，成本最低；人数再多或者要长期开，老老实实弄一个公网 IP，电信宽带可以打客服申请，租机器的话直接买独立 IP 那档。

## serverconfig.xml 里真正影响体验的十项

配置项很多，多数保持默认就好。这一份清单覆盖了玩家实际会抱怨的部分。

| 参数 | 说明 |
| --- | --- |
| `SERVER_NAME` / `SERVER_DESCRIPTION` | 服务器列表里显示的名字和描述 |
| `SERVER_PORT` | 默认 26900，必须和端口转发一致 |
| `SERVER_MAX_PLAYERS` | 示例值 6，按你的机器和带宽定，不是上限 |
| `GAME_WORLD` | `Navezgane` 是固定地图，`RWG` 是随机生成。RWG 更吃内存和生成时间 |
| `GAME_DIFFICULTY` | 0 到 5，0 最简单，5  nightmare |
| `PLAYER_KILLING_MODE` | PvP 相关，示例值 3 |
| `LOOT_RESPAWN_DAYS` | 战利品刷新天数，默认 3 |
| `BloodMoonFrequency` | 血月频率，直接决定服务器的压力峰值 |
| `EAC_ENABLED` | 反作弊开关，默认开 |
| `ADMIN_STEAM_IDS` | 管理员的 SteamID64，多个用空格隔开 |
| `DISABLED_NETWORK_PROTOCOLS` | 留空，两个协议全开 |
| `ALLOW_CROSSPLAY` | Linux 服保持 false |

两个提醒。`SERVER_VISIBILITY` 这个 0/1/2 的取值，不同版本里的注释说法不一致，有的写 0 私有 / 1 公开 / 2 列出，有的写 0 私有 / 1 仅好友 / 2 公开，改完自己实测一遍最稳。另外，管理员的 SteamID64 是 17 位、以 765611 开头的数字，填错一位就等于没给自己权限。

改完配置都要重启。用一键脚本的话注意一点：它的逻辑是每次更新时用 shell 变量重新写入 serverconfig.xml，所以你直接手改 xml，下一轮自动更新会被覆盖回去，配置要改在脚本的配置文件里。

## EAC 和模组：二选一

装了跟反作弊冲突的模组，就得把 `EAC_ENABLED` 改成 `false`，这是硬性的。代价要提前想清楚：关掉 EAC 的公开服，基本等于对作弊敞开。淘宝上一直有卖“过 EAC、上帝背包、拆家飞天”这类修改器的，标价一块钱，这不是什么地下市场，是公开售卖的现象。你自己跟朋友关门玩无所谓，一旦挂到公开列表招人，开着 EAC 至少能挡掉一部分。

不想关 EAC 又想要模组内容，先确认那个模组本身是否与反作弊兼容，兼容就不用动开关。

## 日志、更新、备份：租来的机器要不要额外做快照

七日杀的日志分两套，别搞混。游戏日志记录玩家进出、掉落、事件，Linux 下是 `/opt/7d2d-server/output_log__*.txt`，用 `7d2d_serverlog` 看。systemd 日志记录服务启停和报错，用 `journalctl -u 7d2d.service -f` 看。更新脚本还有自己的日志 `/var/log/7d2d-update.log`，带时间戳。

有两件事会让人丢东西。一是**旧日志超过 30 天会在更新时自动清掉**，你想留证据就得自己另外存。二是**自动更新会重写 serverconfig.xml**，前面说过。

备份该备的是 `Saves` 和 `Worlds` 两个目录，用 cron 或任务计划程序定期打包，需要异地留档就同步到对象存储。租来的机器，面板里如果能做快照，开一个每天的快照比什么都省事；不能做快照就老老实实跑定时打包。

## 几个常被问到的问题

**4 GB 内存到底能带几个人？**
三到四个，且地图别开太大。五个人以上、又要长期挂，建议 6 GB 起。

**能用手机开服吗？**
不行。七日杀服务端是 x86 程序，手机跑不了，云手机也不行。

**端口都开了还是连不上？**
先按前面的五步排查，最常见的是 `DISABLED_NETWORK_PROTOCOLS` 没留空，或者 `GameName` 里有冒号。

**换地图会丢档吗？**
会。`GAME_WORLD` 和 `WorldGenSeed` 一变就是新世界，旧存档还在 `Saves` 目录里，但服务端不会自动加载它。换之前先备份。

**Linux 服 Windows 朋友能进吗？**
能，但 `ALLOW_CROSSPLAY` 保持 `false`。开了跨平台兼容模式反而多出一堆限制，比如 `LootRespawnDays` 只能填 -1、0 或大于等于 5。
